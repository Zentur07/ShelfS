6 ноября 2026. Windows, Django 5.2.19, PostgreSQL 17.11, Mailpit 1.33.0.

`manage.py test library --noinput --verbosity 1`: **46 пройдены, 0 ошибок, 0 пропущено**. Django check: проблем нет. Тесты используют отдельную временную базу.

Проверены регистрация, хеширование, уникальный email, роли, подтверждение и повторная ссылка, каталог и поиск кириллицы без учёта регистра, отзывы и экранирование HTML, бронь и повторные запросы, отмена с подтверждением, CSRF, выдача и возврат, ограничения, история и защита чужих записей, письма и повторы после ошибок.

Отдельные существенные проверки:

- Два потока с разными соединениями PostgreSQL одновременно бронируют последний экземпляр: один успех, один отказ, одна бронь.
- Ошибка сохранения брони во время выдачи откатывает и созданный Loan, и изменение брони.
- История 105 выдач и 105 броней доступна по страницам; чужие записи не видны. Отзывы сверх прежнего лимита 50 доступны.
- GET отмены и POST без подтверждения не меняют бронь. POST с confirmed=yes требует CSRF.
- Будущее сообщение имеет scheduled_at, не уходит раньше срока, отправляется в срок и отменяется после возврата.
- Создание пользователя суперпользователем через админку работает без username.

OSError/RuntimeError в журнале тестов ожидаемы: тесты намеренно моделируют почтовые отказы.

## Границы

Публичный сервер, HTTPS, внешние SMTP-ящики, массовая нагрузка и GitHub Actions не испытывались. Готовность относится к согласованному локальному показу. После переноса выполните запуск и тесты на новом компьютере. SMTP и база не дают гарантии ровно одной доставки при аварии между приёмом письма и сохранением результата.
